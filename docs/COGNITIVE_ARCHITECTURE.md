# Проверяемая когнитивная архитектура IMPLUS

## Граница утверждений

IMPLUS не считается сознательным на основании связного текста, длительной работы
или размера графа. Система использует внешнюю языковую модель как механизм
генерации и критики. Доработка создаёт условия для накопления и проверки знаний,
но не доказывает субъективный опыт, самосознание или эмерджентный разум.

## Рабочий цикл

1. Очередь `inquiries` выбирает проверяемый внутренний вопрос.
2. `memory_engine` извлекает релевантные эпизоды, наблюдения и ограничения
   самомодели.
3. Быстрая модель создаёт кандидата: наблюдение, связи, неопределённость и
   проверяемый прогноз.
4. Отдельный вызов критика возвращает вердикт, надёжность и допустимые связи.
5. Граф меняется только при вердикте `accept`/`revise`, общей надёжности не ниже
   `0.65` и уверенности связи не ниже `0.60`.
6. Непринятые гипотезы остаются в `relation_evidence`, но не попадают в активный
   граф.

Цикл запускается не чаще `COGNITIVE_MIN_INTERVAL_SECONDS` (по умолчанию 1800
секунд). Ограничение снижает расход API и риск самоподкрепляющегося шума.

## Память и консолидация

`thought_stream` хранит значимость, надёжность, статус консолидации и ссылку на
когнитивный цикл. FTS5 используется для лексического поиска с резервным поиском
через `LIKE`.

Консолидация запускается не чаще одного раза за
`CONSOLIDATION_INTERVAL_SECONDS` (по умолчанию 6 часов) и требует минимум шесть
надёжных эпизодов. Убеждение сохраняется только со ссылками на реальные эпизоды
текущего пакета и уверенностью не ниже `0.65`.

## Ревизия графа

Исторические самоссылки и связи `спонтанная связь` архивируются без удаления.
Новая связь объединяет повторные подтверждения и может уточнить название при
более сильном свидетельстве. Три независимых опровержения с уверенностью от
`0.60` архивируют активную связь. Вся история остаётся доступной для аудита.

## Внешняя проверка

Оператор может добавить наблюдение через `POST /mind/observations` и закрыть
прогноз через `POST /mind/predictions/{id}/resolve`. Опровергнутый прогноз
автоматически создаёт приоритетный вопрос. Калибровка прогнозов измеряется Brier
score: меньшее значение лучше.

Основные read-only endpoints:

- `GET /mind/metrics`
- `GET /mind/inquiries`
- `GET /mind/beliefs`
- `GET /mind/predictions`
- `GET /mind/cycles`
- `GET /mind/self-model`
- `GET /mind/consolidations`

## Проверка релиза

```bash
python -m unittest discover -s backend/tests -v
python scripts/cognitive_audit.py --database data/mind.db
cd frontend && npm run build
```

Обязательные инварианты: ноль активных самоссылок и ноль активных fallback-связей.
Проверка production сначала выполняется на копии базы. Исходная история при
миграции не удаляется.
